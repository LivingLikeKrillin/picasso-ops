# Picasso Ops 후속 UX 검토 — 2026-10-10

검토 근거: 현재 React 소스, API 계약, 개편 후 API 대역 화면 촬영본. 직전 전체 스택 E2E 통과는 기능 연계 근거이며, 사용성 검증을 대신하지 않는다. 이번 검토는 설계 평가이며 아래 제안은 아직 구현되지 않았다.

## 판단

시각 스타일과 로봇 도입 흐름은 정리되었지만, 운영·임무·설정·이력에서는 사용자에게 데이터 해석과 화면 간 정보 연결을 맡기는 부분이 크다. 특히 완료 근거, 관측과 사람 판단, 재기동 복원, 버전 추적이라는 시스템의 강점이 여러 표와 상세 항목에 흩어져 있다. 다음 개편의 중심은 운영자가 상황을 파악하고 근거를 확인해 조치하는 흐름이다.

## 제안하는 운영 구조

- 개요: 현재 관측 범위의 진행 작업, 판단이 필요한 인시던트, 서비스별 조회 상태. 예외를 우선 노출한다.
- 작업: 목록 → 작업 상세. 신규 작업 요청과 배정 판정은 하나의 흐름으로 제공한다.
- 예외 대응: 미해결/판단 가능/읽기 전용 상태를 구분하고 관련 작업과 기체로 이동한다.
- 응답 기록: 작업별 응답 내용과 송신·중복 억제 결과를 확인한다. 실제 상위 시스템 ACK가 없으므로 수신 완료로 표현하지 않는다.
- 셀 대역: 모의 설비 관측·신호 조작을 별도 하위 화면으로 둔다. 일반 운영 개요를 차지하지 않게 한다.

## 화면에서 드러내야 할 제품 가치

1. 작업이 어디까지 진행됐고 무엇 때문에 멈췄는지 파악한다.
2. 물리 완료, 요구 근거 충족 여부, 사람의 판단, 응답 송신 상태를 각각 확인한다.
3. 판단의 대상과 근거·사용 버전을 확인하고 필요한 조치를 실행한다.
4. 재기동 뒤 복원·보류·포기한 실행과 이전 인스턴스 기록의 관계를 추적한다.
5. 설정·임무 변경이 언제부터 어느 작업에 적용되는지 확인한다.

단순 완료율이나 로봇 가동률은 현재 응답만으로 정확히 계산하기 어렵다. 요약 지표는 출처·현재 인스턴스·조회 범위를 명시하고 불통 시 0 대신 모름/직전 값으로 표현한다. 모델/기체의 시운전 완료를 모든 임무에 대한 배정 가능으로 확장하지 않는다.

## 권장 구현 순서와 완료 기준

1. 운영 개요·작업 상세·인시던트 연결 및 핵심 상태 표현. 사용자가 ID를 복사해 다른 표를 찾지 않아도 한 작업을 추적한다.
2. 예외 판단 화면·사유 보존·중요 조작 확인·탐색/입력 보존. 거절·응답 모름·재기동 중에도 대상과 이유가 사라지지 않는다.
3. 임무 변경 검토·설정 적용 상태·이력 탐색. 변경 전후와 실제 적용 범위를 확인한다.
4. 기존 단위 테스트와 전체 스택 E2E를 변경된 사용자 여정에 맞춰 갱신한다. 작업 요청 → 보류 → 근거 확인 → 판단 → 재개 → 송신 기록을 화면 간 수동 ID 대조 없이 검증한다.

데모의 대표 장면은 운영자 판단이 필요한 예외에서 시작해 근거 확인, 재작업, 작업 완료, 응답 기록으로 이어지는 흐름으로 권장한다. 이 흐름이 미들웨어와 오케스트레이션의 구현 가치를 직접 보여준다.
