# 상위 결과 버전과 수신 확인(ACK)

> 최신 구현: [상위 업무 중심 후속 7개 구현 및 검증](upstream-followups-2026-10-11.md). 아래 내용은 해당 단계의 기록이다.

2026-10-11. 영속 접수 단계에 이어 Mock MES의 조회 기반 결과 수신 확인을 구현했다. 실제 MES·PLC·로봇 검증을 의미하지 않는다.

## 동작과 책임

Ops가 접수 상세 또는 최신 결과를 조회할 때, 호스트의 jobResponse를 관측해 불변 스냅샷으로 저장한다. 물리 상태만으로 결과를 만들지 않는다. 일지 저장 차단 실행과 현재 실행 상태에 맞지 않는 이전 작업 응답은 새 결과로 발행하지 않는다.

결과에는 원천 주문·접수·내부 작업·로봇·미션 버전·호스트 인스턴스·실행 ID와 전체 jobResponse(요구/도달 근거, 미완료·불명 단위, 잔여 파지, 운영자 필요 여부)를 보존한다. SHA-256은 snapshot의 JSON 객체 키를 재귀 정렬한 UTF-8 직렬화 값에 적용한다. 배열 순서는 유지한다. 외부 호출자는 서버가 반환한 resultHash를 그대로 ACK에 사용한다.

접수별 결과 버전은 1부터 증가한다. 같은 호스트 인스턴스·실행 ID·작업 응답 ID은 한 번만 저장하며, 이미 저장된 응답과 낮은 작업 버전의 응답은 새 결과를 만들지 않는다. 상세 관측은 접수별 잠금으로 직렬화한다. 호스트의 jobResponse.version은 작업 버전이므로 같은 작업 버전에서도 새 jobResponseId가 생기면 별도 결과를 저장한다. 재작업 후 새 호스트 응답을 관측하면 별도 결과 버전으로 저장한다. 호스트 재기동으로 출처 인스턴스가 바뀐 결과도 새 버전이다. 첫 관측 스냅샷은 후속 조회로 수정하지 않는다. ACK 시각만 별도 메타데이터로 갱신한다.

조회 결과의 recordedAt은 Ops가 저장한 시각이며 로봇의 물리 완료 시각을 의미하지 않는다. 작업 응답의 모든 중간 버전을 수집하는 이벤트 구독이나 백그라운드 수집기는 아직 없다. 폴링 사이에 지나간 버전은 보존되지 않을 수 있다.

## API

모든 외부 경로는 기존 서버 설정 Bearer 인증과 원천 시스템 격리를 사용한다.

| 경로 | 의미 |
|---|---|
| GET /integration/v1/job-orders/{receiptId}/results/latest | 현재 호스트를 관측한 뒤 저장된 최신 결과 반환. 호스트 단절 시 기존 저장 결과 유지. 실행하지 않은 작업 요청(`REJECTED`·`UNASSIGNED`)에는 결과 버전이 없어 404 `RESULT_NOT_READY` 이고 콜백(`WorkResultDelivery`)도 없다. 출발 결품의 대체 위치는 상태 조회 `GET /integration/v1/job-orders/{receiptId}` 에서만 읽는다. |
| GET /integration/v1/job-orders/{receiptId}/results/{version} | 해당 저장 버전만 조회. 호스트 호출 없음 |
| POST /integration/v1/job-orders/{receiptId}/results/{version}/ack | 정확한 버전·해시의 수신 확인. 같은 ACK는 같은 최초 시각을 반환 |

결과 응답: `{version, resultHash, snapshot, recordedAt, acknowledgedAt}`. 업무 거절·미배정은 기존 접수 상태와 사유로 조회하며 호스트 작업 응답이 없으므로 결과 스냅샷을 생성하지 않는다. 결과 미생성/없는 버전/다른 출처는 404, 인증 누락은 401, 해시 불일치는 409다. ACK 본문은 4KiB 이하 JSON 객체이며 `{"resultHash":"서버가 반환한 64자리 SHA-256"}`만 허용한다.

업무 시스템은 결과를 조회하고 자체 저장·처리를 완료한 뒤 그 버전과 해시를 ACK해야 한다. 이전 결과 ACK는 최신 결과의 ACK 상태에 영향을 주지 않는다. 결과 저장과 ACK는 접수 행 잠금으로 직렬화한다. 수신 확인 자체는 로봇 명령이나 작업 재제출을 발생시키지 않는다.

## Mock MES 시연

`node scripts/mock-mes.mjs order.json --poll --ack`는 한 번 접수하고 종결 상태의 저장 결과를 출력한 뒤, 명시한 --ack 옵션에 따라 해당 버전·해시를 확인한다. ACK와 주문 제출은 자동 재시도하지 않는다. 이 옵션은 PoC 시연용이며 실제 MES는 자체 결과 저장을 완료한 뒤 ACK해야 한다.

## 화면

상위 작업 요청 상세에 저장된 최신 결과 버전, 저장 시각, 해당 버전의 MES 수신 확인 시각/대기 상태와 불변 스냅샷을 추가했다. 브라우저에서 MES 대신 ACK하는 버튼은 제공하지 않는다. 결과 전달 확인은 외부 호출 주체가 수행한다.

저장된 결과는 현재 실행 상태와 다를 수 있다. 특히 재작업 중에는 이전 결과를 최신 물리 상태로 해석하지 않아야 한다. 현재 호스트 조회 실패도 화면에 별도로 남는다.

## 경계와 남은 작업

이 ACK는 **특정 결과 버전의 수신 확인**이다. 품질 승인·업무 완료 승인·근거 E3 승격을 의미하지 않으며 호스트 내부의 결과 송신 ACK와도 별개다. PHYSICALLY_DONE을 단일 업무 성공 값으로 축약하지 않는다.

callback 발송·재전송, background 결과 수집, 이전 결과 목록 탐색 UI, 접수 중단 복구, 수동 작업 접수 통합, 전용 작업 메뉴·운영 개요, 미션 배포 버전 고정은 남아 있다. 현재 단일 Mock MES 인증은 생산 환경의 다중 주체 IAM을 대체하지 않는다.

## 검증

UI 전체 175개와 Ops 백엔드 전체 274개(실패·오류·스킵 0)가 통과했다. 결과/접수 DB 회귀는 15개다. TypeScript/Vite 빌드·oxlint, Ops 배포본 생성 및 main의 Picasso 모듈 비의존 검사가 통과했다. Mock MES CLI는 구문과 --help를 확인했으며 CLI 자체의 실접수는 실행하지 않았다. DB 기반 회귀에는 결과 보존/재조회/저장소 재생성, 동시 결과 관측, 이전 응답 지연, 일지 차단, 재작업 중 이전 응답 제외, 버전별 멱등 ACK, 해시 충돌, 출처 격리와 인증을 포함한다. 전체 스택 E2E에는 실제 HTTP 결과 조회·해시 충돌·중복 ACK·Ops 수신 확인 표시를 추가했다.

실제 HTTP 화면을 API 가로채기 없이 촬영했다. [데스크톱](style-preview/upstream-result-ack-fullstack.png) · [390px 모바일](style-preview/upstream-result-ack-mobile-fullstack.png). 모바일 문서 너비 390px로 가로 넘침이 없고, 두 캡처에서 물리 완료·결과 v1·MES 수신 확인을 확인했다.

전체 스택 Playwright E2E 1개가 4.8분에 통과했다. 실제 HTTP로 인증 누락 401, 결과 조회, 해시 불일치 409, 최초·중복 ACK, 불변 버전 재조회와 Ops 수신 확인 표시를 검증하고 기존 기체 등록·미션·장애·운영자 재작업·관측 불명 시나리오까지 수행했다.
