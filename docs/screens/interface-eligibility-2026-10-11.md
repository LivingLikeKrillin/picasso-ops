# 호출 계약 기반 실행 전 배정 확인

2026-10-11. 상류의 업무 입력을 로봇 배정 조건과 연결한다. 기존 기본 업무 폼뿐 아니라 새로 등록한 미션도 같은 판정 경로를 사용한다.

## 운영 흐름

1. 공개된 호출 계약에서 실제 입력을 작성한다.
2. **이 입력으로 배정 가능 확인**을 누른다.
3. 서버가 계약의 매핑과 현재 실행 배포를 적용한 정규화 작업을 만든다. 고정 미션 버전으로 기체별 판정을 요청한다.
4. 기체별 시운전·연결·진행 중 실행·요구 스킬·제공 스킬·불가 사유를 확인한다.
5. 배정 가능한 기체가 있으면 작업 지시 확인란을 선택하고 요청한다.
6. 생성된 접수의 링크로 실행·저장 결과·확인 이력을 추적한다.

기체 제공 스킬은 실행 호스트가 하위 포트에서 읽은 capability 보고다. 요구 스킬은 고정된 미션을 해당 입력으로 펼친 ROBOT 경로 단위에서 구한다. 설비 대기 단위를 로봇 스킬로 요구하지 않는다. 목록을 못 읽었으면 모름, 읽었고 비었으면 없음으로 구분한다.

## API

`POST /api/mission-interfaces/{id}/{version}/eligibility`

```json
{ "input": { "assets": [{ "id": "T1", "location": "bay-7" }] } }
```

응답은 `interfaceId`, `interfaceVersion`, `jobOrder`, `eligibility`다. `jobOrder`에는 미션·배포 버전·요구 근거와 매핑 결과가 포함된다. `eligibility`는 기존 기체별 배정 판정 구조이며 호스트 행에 `requiredSkills`, `availableSkills`를 추가했다. 예전 호스트가 필드를 제공하지 않으면 모름으로 표시한다.

이 API는 로컬 Ops PoC의 조회 API다. POST이지만 작업 접수·제출·감사 조작을 생성하지 않는다. 입력은 64KiB 이하 JSON 객체이고 `input` 이외 최상위 필드는 거절한다. 미공개 계약은 409, 없는 계약은 404, 매핑·스키마 오류는 400이다. registry·호스트를 못 읽은 경우 판정 결과에서 모름과 배정 불가를 유지한다.

## 판정과 실제 제출의 관계

미리보기는 기체를 예약하지 않는다. 스킬 적합은 스킬 이름의 포함 관계이며 파라미터 범위·현장 안전·물리 완료·품질 승인까지 보장하지 않는다. 실제 제출은 기존 Ops와 실행 호스트의 게이트를 다시 통과한다. 판정 후 기체가 사용 중이거나 연결을 잃었다면 실제 제출에서 미배정될 수 있다.

화면은 입력·공개 상태·조회한 배포 버전·호출 주체가 바뀌면 이전 판정을 사용하지 않는다. 새 작업은 정상 판정과 배정 가능 기체가 있어야 전송할 수 있다. 조회 실패 때 이전 성공 판정을 유지하지 않는다. 자동 예약이나 판정 만료 시간을 구현한 것은 아니므로 오래된 관측은 다시 확인한다.

새 화면의 invoke 요청에는 판정 응답의 `expectedDeploymentVersion`을 함께 보관·전송한다. 서버는 새 접수를 준비할 때 실제 선택한 배포와 비교한다. 배포가 다르면 로봇에 제출하지 않고 사유가 있는 **REJECTED 접수**를 반환한다. 영속 접수 응답이므로 최초 HTTP 상태는 202이고 본문의 상태가 거절이다.

기존 요청 재확인은 현재 배포나 공개 상태를 다시 검사하기 전에 동일 요청 ID·원본 내용의 기존 접수를 반환한다. 배포 변경 후에도 기존 요청을 새 작업으로 만들지 않는다. 화면은 이 ID와 기대 배포 버전을 새로고침까지 보관한다. 이전 형식으로 보관된 요청에는 기대 배포 버전이 없어도 재확인을 허용한다. 기존 호출 클라이언트의 호환성을 위해 invoke의 기대 배포 버전은 선택 항목이며, 외부 Mock MES 주문 envelope는 변경하지 않았다.

배포 변경으로 거절된 접수는 확인 후 **새 계약 요청 작성 → 배정 가능 재확인**으로 새 요청을 만든다. 미배정·응답 불명 요청을 새 ID로 반복 전송하는 방식으로 처리하지 않는다.

## 검증

- 백엔드: 고정 배포·실제 입력 사용, 신규 미션, 조회의 무변경성, 미공개·잘못된 입력·없는 계약, 호스트 모름, 배포 변경 거절·동일 ID 재확인, 제출 시 재판정
- 제조 통합 시나리오: 두 기종 모두 공통 검사 가능, 첫 기체 사용 중에는 다른 기체만 가능, 실제 실행 결과까지 연결
- UI: 판정 전 새 호출 차단, 입력·배포 변경 시 판정 무효화, 조회 실패·모름, 응답 소실 후 동일 요청 확인
- 브라우저: 기본·신규 미션의 실제 사전 판정 → 호출 → 완료 → 접수 비교·단절 복구, 데스크톱·모바일 표시
