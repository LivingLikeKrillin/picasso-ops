# 미션 관리 구현 — 2026-10-11

## 구현한 사용자 여정

새 미션 만들기 → 입력 스키마·작업지시 변환·표본 등록 → 실행 정의 초안 저장 → 검증 → 모의 실행 → 숫자 버전 활성화 → 호출 계약 작성 → 숫자 버전 배포 → 공개 → 운영자/상위 시스템 접수 → 실행·결과 추적.

새 미션에는 내장 CODE 정의가 없다. 등록만으로 실행하거나 공개할 수 없으며 검증된 숫자 버전을 명시적으로 배포해야 한다. 초안별 표본 작업을 호스트 DB에 저장한다. 미션 URL과 초안의 소유 미션을 대조하며 다른 미션 초안의 조작을 차단한다. 등록 응답 유실 시 세션에 보관한 같은 입력으로 재확인한다. 동일 ID·동일 내용은 멱등이며 다른 내용으로 덮어쓰지 않는다.

## API와 데이터

- GET/POST `/api/mission-profiles`: 불변 사용자 정의 업무 등록/조회.
- `/api/job-contracts`: 기존 업무와 등록된 업무 통합 제공.
- 기존 미션 초안·검증·모의 실행·활성화 API와 호출 계약 preview/deploy/invoke 확장.
- Ops V11: 미션 프로필·호출 계약의 업무 참조 제약. Host V3: 초안별 표본 작업.
- [점검 프로필 예제](../examples/mission-profile-inspection.json).

## 지원 경계

입력 스키마는 JSON Schema 부분집합(object/array/string/integer/number/boolean, 필수 값, 길이·개수·범위·enum)이다. 임의 스크립트나 외부 참조는 지원하지 않는다. 변환은 배열에서 설비 ID·속성 및 자재 수량을 만드는 선언적 규칙이다. 입력 계약 변경은 새 업무 ID로 등록하고 실행 정의는 숫자 버전으로 관리한다.

실행은 현재 Picasso의 순차 unit/wait와 어댑터 제공 스킬 범위다. 자유로운 DAG·조건 분기·임의 코드·실물 로봇 스킬 생성은 범위 밖이다. 새 업무 등록은 현장 적합성이나 산업안전 인증을 의미하지 않는다.
